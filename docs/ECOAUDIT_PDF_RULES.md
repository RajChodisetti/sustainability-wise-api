# EcoAudit PDF rules

This document is the source of truth for the EcoAudit report generated by `src/routes/ecoaudit/pdf.ts`. Changes to the report renderer must preserve these rules or update this file and the PDF regression checks in the same change.

## Generation workflow

1. The web portal must create a background job with `POST /v1/ecoaudit/audits/:auditId/report/pdf/jobs`.
2. The portal must poll `/v1/pdf/jobs/:jobId` until the job is complete, then download `/v1/pdf/jobs/:jobId/download`.
3. The direct synchronous route remains a legacy/API compatibility path. It must use the same `renderEcoAuditPdf` renderer, but the portal must not offer a second generation workflow.
4. Both report modes, zone filters, photo metadata, storage, and OneDrive backup must pass through the same background job inputs.
5. `zoneIds` remains the optional zone filter. `zoneOrder` is an independent, optional presentation order so reordering all zones never excludes unzoned equipment or changes legacy filtering semantics.

## Page and frame rules

- Output is A4. The renderer reserves 56 px at the top and 30 px at the bottom for the page frame, with no left/right browser margin.
- The navy report header repeats at the top of every page.
- The footer repeats at the bottom of every page and closes the page frame.
- The renderer stamps the white canvas, header, footer, and outer side borders onto every generated page after browser layout so browser header/footer fragmentation cannot remove them.
- The content cell has 28 px left/right padding, 18 px top padding, 40 px bottom padding, and 2.5 px navy side borders.
- Header, content side borders, and footer must form a continuous visual page frame. No content may render outside it.
- Page background is white and all report colours must be printed (`printBackground: true`).

## Page-start and pagination rules

- The cover and executive summary appear only once, at the start of the report.
- Executive-summary zone, photo, category, and total-item values describe the full selected report scope, even when a large report is rendered in several chunks. Empty selected zones remain part of the zone total.
- Report zones default to deterministic creation-time/ID order. A supplied `zoneOrder` takes precedence, and equipment follows the same zone sequence in both report modes.
- In **Report by Zone**, a zone header stays with its first photo/category/item block. A zone may use the remaining printable area; it must not create an unnecessary blank or partly empty page.
- Zone headers use the zone name without a generated numeric badge; chunk boundaries must never create duplicate or restarted zone numbers.
- A continuation PDF chunk begins directly with its first zone or equipment content on a clean framed page; it must not add a blank page.
- Major section, subsection, zone, item, note, and photo headings must stay with the content immediately following them.
- Photo grid rows and large-photo blocks are atomic and must not split across pages.
- Normal cards may split only when their content is taller than the remaining printable area. When a split is unavoidable, the border and padding must be cloned on both page fragments so there is no cut/open border.
- Orphaned headings, captions, single text lines, and empty trailing cards are not allowed.

## Border rules

- Equipment/item cards use a 1 px light-blue border and a 3 px navy left border.
- Note and observation cards retain their coloured left rule and background on every page fragment.
- Section and zone headers use the established navy and pale-blue hierarchy; they must not be restyled by portal UI changes.
- Every PDF photo has a visible 1 px `#CBD5E1` border, white background, small internal padding, and a 4-5 px corner radius.
- Borders must never be clipped at a page edge or disappear when an item continues on another page.

## Photo rules

- Images use their natural aspect ratio and must never be cropped or stretched.
- The default/smaller setting uses the compact grid: two columns for one or two photos and three columns for larger groups, with a maximum image height of 172 px.
- **Large in PDF** renders one photo across the available content width with a maximum image height of 370 px.
- Each photo caption appears directly below its image and may wrap, but it must stay with that image.
- A custom photo label overrides the generated field label. Empty custom labels fall back to the standard field label.
- Photo metadata is stored on the zone/equipment record in `photoDescs`:
  - single photo: `fieldName`
  - array photo: `fieldName.index` (for example, `extraPhotos.0`)
  - value: `{ "name": "Custom label", "largeInPdf": true }`
- Legacy array registry names written as `fieldName_0` and canonical names written as `fieldName[0]` must both resolve to `fieldName.0`.

## Large-report rules

- Reports at or below 120 photos and 120 MB of raw photo data render as one document.
- Larger reports render in inline chunks targeting 50 photos, then merge in order.
- Only the first chunk contains the cover/executive summary, and only the final chunk contains the end-of-report block.
- Every chunk uses the same page frame, pagination, border, caption, and photo-size rules.

## Release verification

Before a PDF change is released:

1. Generate both report modes through the background job.
2. Include at least two zones, multiple equipment types, long notes, compact photos, large photos, and custom captions.
3. Render every PDF page to PNG with Poppler and inspect the first page, every zone header, all page transitions, photo rows, and the final page. If the local Poppler build does not clear its raster canvas between pages, render one page per invocation.
4. Confirm there are no clipped words, open/cut borders, orphaned headings, blank pages, stretched photos, missing captions, or content outside the page frame.
5. Confirm the portal still exposes only the background-job workflow.
6. Reorder at least three zones in the portal and confirm both report modes follow that sequence, including a report large enough to render in multiple chunks.
7. Confirm the executive summary reports full-report zone/photo/item totals rather than the first chunk's totals, and confirm no zone header contains an auto-generated number.
